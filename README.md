# منصة إدارة ونشر الوظائف في جروبات Facebook

تطبيق محلي عربي RTL مبني بـExpress 5 وReact لإدارة اكتشاف الجروبات وتحليلها، طلبات الانضمام، الوظائف، حملات النشر والمتابعة. يعمل في `DRY_RUN` افتراضيًا ولا يتجاوز CAPTCHA أو 2FA أو فحوصات Facebook الأمنية.

> تنبيه: أتمتة واجهة Facebook ليست API رسمية وقد تؤدي إلى تقييد الحساب. استخدم حسابًا مخولًا، راجع شروط Meta وقواعد كل جروب، ولا تستخدم النظام لإرسال محتوى عشوائي أو غير مرغوب.

## المتطلبات

- Windows 10/11 وNode.js 22+ وGit.
- اتصال إنترنت لتثبيت الحزم وChromium.
- لا يلزم Redis أو Docker؛ SQLite مدمجة.

## الإعداد الأول

نفّذ من PowerShell داخل مجلد المشروع (Node.js 22.19 أو أحدث):

```powershell
corepack pnpm install
corepack pnpm run setup
corepack pnpm admin:create
corepack pnpm browser:install
corepack pnpm build
```

`run setup` ينشئ `.env` بمسار قاعدة بيانات مناسب لمجلدك وإعداد جلسات عشوائي، ويطبق migrations المحفوظة دون إعادة ضبط البيانات. استخدم `run setup` حرفيًا؛ `pnpm setup` أمر مختلف لإعداد pnpm نفسه. عند وجود `.env` يحتفظ به البرنامج. لا تنشر `.env` أو ملفات الجلسات.

`db:seed` يضيف الإعدادات والقوالب فقط. بيانات العرض لا تُضاف إلا بأمر `corepack pnpm db:seed:demo` ومع `NODE_ENV` غير production.

## التشغيل

```powershell
corepack pnpm dev
```

- Dashboard: http://localhost:5173
- API health: http://127.0.0.1:3000/api/health
- OpenAPI: http://127.0.0.1:3000/api/docs
- تبدأ الأتمتة بحالة `STOPPED`. سجّل الدخول ثم افتح صفحة «إعدادات فيسبوك».
- اضغط «فتح جلسة فيسبوك»، وسجّل الدخول يدويًا في Chromium، ثم أغلق الجلسة من اللوحة لتسليم profile إلى Worker.
- أبقِ `DRY_RUN=true` حتى تتأكد من البحث والتحليل والاستهداف. تحويله إلى `false` يحتاج إعادة تشغيل العمليات.

لا تفتح Chromium العادي على مجلد `data/browser-profile` بالتزامن مع التطبيق؛ lock الملف يمنع تلف الجلسة.

## أوامر الصيانة

```powershell
corepack pnpm db:generate
corepack pnpm db:migrate
corepack pnpm db:seed
corepack pnpm typecheck
corepack pnpm lint

```

قاعدة البيانات في `data/app.db`، وملف المتصفح والصور ولقطات الأخطاء تحت `data/`. هذه الملفات مستبعدة من Git. خذ نسخة احتياطية من مجلد `data` بعد إيقاف API والـWorker.

## التعامل مع التحقق اليدوي

عند CAPTCHA أو انتهاء الجلسة أو Security Check، تتحول المهمة إلى `MANUAL_ACTION_REQUIRED` وتتوقف بوابة الأتمتة. افتح جلسة Facebook من اللوحة وأكمل التحقق بنفسك، أغلق نافذة الجلسة، ثم استأنف الأتمتة. لا توجد آلية stealth أو تجاوز أو إجابات عضوية مختلقة.

## حدود التكامل والاختبار الحي

تغيّر Meta واجهة Facebook باستمرار. الـselectors معزولة في `packages/facebook-automation/src/selectors.ts` وتستخدم roles وlabels باللغتين، لكن يجب اختبار البحث والانضمام والنشر يدويًا على الحساب والواجهة الفعليين قبل تعطيل DRY RUN. الاختبارات الافتراضية لا تتصل بـFacebook.

## البناء للإنتاج المحلي

```powershell
corepack pnpm build
corepack pnpm --filter @app/api start
corepack pnpm --filter @app/worker start
corepack pnpm --filter @app/dashboard exec vite preview --host 127.0.0.1
```

استخدم HTTPS عبر reverse proxy إذا أصبحت اللوحة متاحة خارج الجهاز، واضبط `DASHBOARD_ORIGIN` و`SESSION_SECRET` وملف `.env` قبل التشغيل.

## استوديو المحتوى — حساب ChatGPT وجروبات حسابك الشخصي

1. من «إعدادات فيسبوك»، افتح الجلسة وسجّل الدخول **بحسابك الشخصي**، ثم افحص تسجيل الدخول وأغلق النافذة لتسليمها للتشغيل.
2. من «استوديو المحتوى»، اضغط «جلب الجروبات من فيسبوك» وشغّل الأتمتة. البرنامج يقرأ صفحة مجموعاتك ويتحقق من زر العضوية لكل جروب. يعرض عدد الجروبات التي أمكن التحقق منها، ولا يحذف عضويات قديمة لمجرد أن نتيجة المزامنة جزئية.
3. اختر الجروبات بنفسك. لا توجد قاعدة «اختيار فارغ يعني النشر للجميع».
4. اضغط «ربط حساب ChatGPT» وسجّل الدخول بنفسك في نافذة مستقلة. ملفها في `data/chatgpt-profile`؛ لا يوجد API key مطلوب ولا تخزين لكلمة مرور الحساب في قاعدة البيانات.
5. اكتب بيانات المحتوى أو استورد بيانات وظيفة محفوظة، وحدد الأسلوب، واضغط «توليد البوست». ستُرسل البيانات وأسماء/أوصاف الجروبات المختارة إلى ChatGPT. النتيجة تحفظ كمسودة؛ ويمكن لصق نص يدويًا إذا تغيرت واجهة ChatGPT أو احتاجت تحققًا.
6. راجع النص وعدله، وحدد موعدًا اختياريًا، ثم علّم تأكيد المراجعة وابدأ الحملة. أي تعديل في النص أو الجمهور يلغي تأكيد المراجعة.
7. راقب التقرير: رابط المنشور المؤكد، الحالة، سبب الفشل، النتائج التجريبية، مراجعة النتيجة اليدوية، وتصدير CSV.

يمكن حفظ المسودات والعودة إليها من القائمة. التوليد لا يحتاج تشغيل عامل فيسبوك؛ جلب الجروبات والنشر يحتاجان تشغيله. عند إعادة تشغيل الخادم أثناء التوليد، تتحول المسودة المتوقفة إلى رسالة مراجعة عند فتحها ولا يعيد إرسال الطلب تلقائيًا.

### ضمانات وحدود التنفيذ

- كل حملة تحتفظ بنسخة المحتوى ووضع التشغيل والجروبات، وطلب إنشائها له مفتاح يمنع تكرار الحملة عند إعادة نفس الطلب.
- تُجهز كل الجروبات، ثم تُرسل المهام على دفعات حسب `maxPostsPerRun`؛ المجدول يستكمل الدفعات التالية كل دقيقة. لا تضيع بقية الجروبات بعد الدفعة الأولى.
- تُسجل نية الإرسال قبل الضغط على «نشر». وجود محاولة غير مؤكدة يمنع إعادة الإرسال الآلية. تأكيد النشر يحتاج محتوى مطابقًا ورابط منشور جديد من نفس الجروب؛ اختفاء رسالة انتظار الموافقة وحده لا يثبت النجاح.
- عند عدم وجود رابط مؤكد لمنشور ينتظر الموافقة، تتم مراجعته يدويًا من التقرير؛ لا تُنسب له منشورات متشابهة من الخلاصة.
- الإيقاف يُفحص قبل الخطوات المؤثرة، ويراقب العامل الحالة كل 300 مللي ثانية ويغلق المتصفح عند الإيقاف. لا يستطيع إلغاء طلب وصل بالفعل إلى Facebook؛ هذه الحالة تبقى للمراجعة.
- صلاحية ملكية المهمة تُجدد أثناء العمل. استرجاع مهمة انتهت صلاحيتها لا يعيد نشر محاولة مسجلة كـ`POSTING`.
- تغيير `DRY_RUN` لا يحوّل حملة تجريبية قديمة إلى حملة حقيقية. أنشئ حملة جديدة بعد مراجعتها.
- تحليل الجروبات يستخرج البيانات الظاهرة فقط، بما فيها الأرقام العربية والنشاط والوصف والموقع إن ظهرت. نقص البيانات المطلوبة يترك الجروب للمراجعة، والقرارات اليدوية لا تُستبدل تلقائيًا.
- ربط Facebook وChatGPT يعتمد على واجهتي المتصفح وليس تكاملًا رسميًا. اختبارات المتصفح تستخدم صفحات محلية ممثلة، ولا تثبت توافق كل واجهة حية أو حساب. يلزم فحص تسجيل الدخول والتوليد والجلب على حسابك، ثم تجربة منشور واحد في جروب تسمح قواعده بذلك قبل التوسع.

## النسخ الاحتياطي والاسترجاع

أوقف الأتمتة، أغلق جلسات المتصفحات، ثم أوقف API والعامل. الأوامر ترفض العمل إذا وجدت عملية تشغيل مسجلة ما زالت حية.

```powershell
corepack pnpm backup
corepack pnpm backup:verify "C:/path/to/data/backups/backup-directory"
corepack pnpm backup:restore "C:/path/to/data/backups/backup-directory" --replace
```

النسخة تشمل قاعدة SQLite وملفات الصور المرفوعة، مع بصمات SHA-256 وفحص سلامة قاعدة البيانات. الاسترجاع يتحقق من النسخة ويحتفظ بنسخة من الحالة الحالية أولًا، ويعيد الأتمتة إلى STOPPED والمهام المعلقة إلى PAUSED. لا تستأنف المهام قبل مراجعة نتائج النشر على Facebook. الاسترجاع إلى نفس المسارات يحافظ على مراجع الصور. ملفات جلسات Facebook/ChatGPT ولقطات الأخطاء غير مضمنة؛ احتفظ بإعدادات الجهاز بصورة منفصلة وأعد تسجيل الدخول عند الحاجة.

إذا بقي ملف قفل قديم بعد تعطل الجهاز: أغلق API والعامل وجميع نوافذ المتصفح الخاصة بالتطبيق، ثم شغّل `corepack pnpm browser:unlock --confirm-closed`. لا يقبل الأمر إزالة قفل تملكه عملية حية.

## التحقق من التغييرات

`corepack pnpm test` ينشئ قواعد بيانات مؤقتة منفصلة لكل ملف اختبار، ولا يقرأ `.env` ولا يسحب مهام قاعدة التشغيل. يتضمن اختبارات الاستهداف والمراجعة، منع تكرار الحملة، استكمال الدفعات، توقف التشغيل، استرجاع النشر غير المؤكد، نسخ البيانات واستعادتها، وواجهات Facebook/ChatGPT المحلية الممثلة. ثبّت Chromium قبل تشغيلها.

فحص الواجهة ببيانات ممثلة، دون حسابات خارجية:

```powershell
corepack pnpm --filter @app/dashboard exec vite --host 127.0.0.1 --port 5174 --strictPort
# في نافذة ثانية
node scripts/verify-ui.mjs
```

يختبر الاختيار والمراجعة والنشر، ويتحقق من عرض الموبايل، ويحفظ صورًا في `test-results/ui`.
